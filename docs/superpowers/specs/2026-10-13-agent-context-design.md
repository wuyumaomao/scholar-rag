# Agent 上下文预算、工具证据缩减与旧轮次摘要

日期：2026-10-13。用于学习 demo。以下选择已通过 grilling 与用户逐项确认；本文件为实施前的最终设计审阅版本。

## 目标与范围

限制每次模型输入规模，完整保存原始历史。优先按需缩小占空间最大的工具结果，再摘要旧轮次，必要时移除旧轮次。模型输入视图持久保存在同一 InMemorySaver 的 AgentState 中，以便下一次调用复用已处理的前缀。重启仍丢失；不改已有 PostgreSQL sessions/messages 存储。

不设置强制“最近五轮”窗口，不照搬简历的 8192 数值。摘要、记忆召回质量与缓存收益不宣称已验证。

## 状态和消息视图

- `messages`：原始消息记录，沿用 MessagesState reducer。上下文处理不删改原始证据；原有无证据回答替换逻辑保持其用途。
- `context_messages`：已裁剪的模型消息视图，采用覆盖更新；复制消息后处理，不原地修改 messages。
- `context_cursor`：已处理原始 messages 的条数。同步时只追加此位置之后的新消息，并推进 cursor。原始已有消息的内容修正按消息 ID 同步到仍保留的对应视图消息，避免旧答案残留；不复活已经移除的历史。
- `context_summary`：旧轮次的结构化摘要，以单独的消息呈现。摘要为不可信历史数据，不具备修改系统规则的权限。
- 每轮更新视图和原始记录时提交一致的 cursor/消息集合。异常重试只处理未同步消息，不重复追加。
- 视图中的完整轮次按 HumanMessage 边界划分；保留的 AI tool_calls 与 ToolMessage 成组存在。

## 预算

配置总预算默认 16384；输出预留取 `llm_max_tokens`（当前默认4096）；估算余量默认1024。有效输入额度 B = 总预算 - 输出预留 - 估算余量，必须大于零。

估算包括实际 SystemMessage、摘要、context_messages 和转换后的工具 schema。使用 LangChain 近似计数及工具 JSON 估算；这是 demo 预算，不是 provider 精确计费或实际上下文上限保证。

- 未超过 B 的80%：保持原始/此前已形成的视图，不主动处理证据。
- 超过80%：逐步处理，争取降到60%。每处理一条结果即重新计算整体占用。
- 一级处理结束后低于或等于80%，即使未到60%，允许正常模型调用。
- 一级处理结束后仍超过80%，进入旧历史摘要/移除层。

## 一级处理：工具专用缩减

候选按当前视图中的工具结果大小降序；状态与错误始终保留。不破坏调用 ID、工具名称和 ToolMessage。

针对 search_paper：

1. 以 file_id + source_id + 完全相同正文判定重复。若正文不同或增加了关联图注，不合并。
2. 重复正文只保留第一次出现的完整版本，后续结果用结构化证据引用代替，明确指向会话中的完整来源。去重不会删除工具响应本身。
3. 从低排名开始移除旧结果中的未受保护证据，留下的证据完整保留正文、来源 ID、页码和章节。标注内容已缩减，不能把截短结果伪装为原始完整结果。
4. 缩减前维护输入视图证据依赖：若去掉正文持有消息而其他消息仍引用它，须从原始历史把完整正文提升到保留的引用位置。只有本次仍需要的来源可这样提升，不恢复整轮历史。
5. 如果全部正文必须移除，保留原检索状态和“证据已因预算移除”的说明，而非误报原检索未命中。

保护范围：当前用户问题及其后完整工具调用链，不按排名移除当前轮独有证据，但可消除完全重复正文。上一轮最终回答中实际引用且能匹配来源的证据也保护。仅引用标识匹配不等于内容已获事实核验；不把返回的全部 sources 当作已引用。

## 二级处理：摘要与回退

一级处理仍高于80%时，选择较旧、完整、未受保护的轮次，与原摘要一起合并为结构化摘要及执行台账。摘要内容：用户问题、来源支持的已得结论、来源标识、工具动作及状态、未完成事项。推测标记为推测，不能升级为事实。被摘要的 ToolMessage 不孤立保留。

使用单独的无工具摘要模型调用，使用已有 LLM 设置；限制摘要输出长度。摘要请求本身必须符合输入预算，超大的旧轮次先采用确定性缩减/分批输入，不能为了压缩发出超预算请求。摘要调用设有限尝试（第一版单次尝试），无空摘要、无无限压缩循环。

摘要失败、无效或未降低占用时，不把它当成成功：回退移除最旧且未受保护的完整轮次，并逐次重新计算。有效摘要可继续保留。摘要格式正确不保证语义正确，后续通过样例检验。

当前轮不参与旧历史摘要。上一轮受保护证据的完整正文留在输入视图；如果其原轮被摘要/移除，提取为带来源的证据消息，不留下悬空工具响应或证据引用。

若已无可处理内容但仍超过80%，返回 `context_limit`，明确任务未完成、不再调用主回答模型、不硬截断保护证据。

## 接入图和 API

独立 context 模块负责同步视图、估算、证据缩减和旧轮次处理。agent() 在每次模型调用前调用该模块，发送实际 SystemMessage + 摘要/保护证据 + context_messages；bind_tools 仍传工具 schema。

State.status 增加 context_limit，route 对此直接 END。若预算检查发生在 tools 返回之后，当前 AI 工具请求已有配对结果，结束提示可直接追加。若未来存在未配对工具请求，先显式关闭它们再结束。

API 保留 thread_id/answer/status/trace，增加可读的 context 信息：处理前后估算输入、额度、保留/移除轮数、去重/缩减数量及摘要是否执行。只记录计数和处理状态，不输出额外内部思维。context_limit 与 tool_limit 明确区分。

原始 sources 是会话检索来源集合，不等于本次模型看见的证据。补充本次可见来源标识用于检查裁剪效果，避免把完整 sources 误认成模型输入。

## 稳定前缀

没有新压力时复用 context_messages，不从 messages 重建全量输入。摘要/缩减会改变前缀；另外现有动态预算 SystemMessage 每次可不同，所以不能承诺缓存命中。缓存优化作为后续独立实验，本版仅保证视图不无故恢复或反复裁剪。

## 验证

离线验证：低压力不裁剪；80%触发/60%停止；逐条最大结果处理；不同正文不误去重；保护当前轮与上一轮引用；去重引用不悬空；完整 tool call/result 配对；视图追加/cursor 和原始历史不变；摘要输入受限、失败回退；无可裁剪内容返回 context_limit；不同 thread 隔离；checkpoint 恢复后视图复用。

图/API 回归覆盖每轮预算重置、tool_limit/no_evidence、现有消息替换与跨论文检查。真实模型可手动用大工具结果及多轮追问验证，近似 token 不作为准确成本数据。
