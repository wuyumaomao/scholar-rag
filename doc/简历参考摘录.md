### 项目经历一：智能旅行规划助手（LangGraph + Multi-Agent 架构）
- GitHub 仓库地址（原文标注）：https://github.com/jiage-agent
**技术栈**：Python 3.13、FastAPI、LangGraph、Tavily、SQLite、Middleware、LangSmith、Pydantic。

1. **功能描述**：基于 LangGraph 图编排与多 Agent 协作构建旅行规划智能体，接收用户需求、日期、预算、出行天数、偏好，自动获取天气、路线等实时情况，完成需求解析、行程编排、预算校验、景点筛选，输出完整可执行旅游方案。
2. **架构设计**：采用 Supervisor 中心化（Hub-and-Spoke）多 Agent 架构，由 Supervisor 节点统一评估全局状态，动态路由到 4 个专职子 Agent（需求提取、信息收集、行程规划、预算/偏好审核）。相比传统线性流水线，支持动态调度与异常重规划。
3. **状态管理**：基于 Pydantic 定义全局 State 对象，通过 LangGraph Checkpointer（SQLite）实现跨节点状态共享与多轮对话记忆，支持断点续跑。
4. **结构化输出**：对每个子 Agent 使用 `with_structured_output` + Pydantic 强校验，解决大模型输出不稳定的问题，配合 `json_mode` 与失败重试，输出格式 95% 以上可被代码消费，基本杜绝 JSON 解析崩溃。
5. **可靠性设计**：设置最大迭代次数，防止 Agent 死循环；工具调用失败自动重试（最多 3 次），异常退出率降低约 70%；引入 Human-in-the-loop 人工审核节点，对敏感决策（如预算超支）进行人工复核，支持人工判定通过/驳回。
6. **工程化落地**：uv 依赖锁定、`.env` 密钥隔离、Docker 容器化、LangSmith 全链路追踪，支持 DeepSeek / 阿里云百炼多模型接入。项目已开源至 GitHub，支持一键 clone 运行。
7. **重构说明**：初版为线性流水线，实践中发现无法应对模糊输入、审核环节僵化、无人介入点。重构为 Supervisor 中心化架构、息收集节点（真实天气 + 路线 API），引入 Pydantic 强校验与 Human-in-the-loop 中断恢复机制。（截图浮层遮住“息收集节点”之前的字；按上下文可能为“信息收集节点”，此处保留可见字样。）

### 项目经历二：智能数据分析助手（LangGraph + Router-Skill + Text-to-SQL）

**技术栈**：Python 3.13、FastAPI、LangGraph、RAG、SQLite、Embeddings、LangSmith、ChromaDB。

1. **功能描述**：基于 LangGraph 构建数据分析 Agent，接收用户自然语言提问，自动完成意图分类、Schema 检索、SQL 生成与结果可视化，输出数据表格与图表，支持查数/排名/趋势/占比/兜底闲聊 5 类场景。
2. **架构选型**：采用 LangGraph + Router-Skill 架构。原因：数据分析任务模式化程度高，Router 将意图分类转化为「选择题」，相比 ReAct 开放式决策，确定性更高，有效避免 LLM 幻觉。
3. **RAG 检索增强**：RAG 定位为 Skill 内部的知识检索基础设施，而非独立 Agent。分为 Schema 索引（解决 LLM 猜错表名/字段名）和业务口径索引（解决“销售额 = SUM(sales_amount)”等业务黑话理解），使用 ChromaDB 构建向量库。
4. **错误自愈机制与幻觉控制**：SQL 执行失败时，将数据库报错信息回传给 LLM 自动重写 SQL，最多重试 2 次（防止死循环），降低因语法错误或字段拼写错误导致的查询失败率；RAG 提供可溯源的引用依据，有效降低大模型幻觉率，SQL 执行成功率从 65% 提升至[最终数值仍被浮层遮挡]。
5. **自动可视化**：根据查询结果自动生成柱状图或折线图，实现从自然语言到可视化报表的端到端闭环。
6. **工程化落地**：使用 FastAPI 封装标准化接口（Swagger 文档），集成 LangSmith 实现全链路追踪，使用 uv 进行依赖与虚拟环境管理。

## 简历 02：基于 nano-cc 的科研论文多轮智能检索问答 Agent



### 技术栈

Python、nano-cc、FAISS、BGE-M3、BM25、RRF、Cross-Encoder Rerank、多级记忆压缩、Claude API。

### 项目介绍

面向科研论文库多轮问答中的指代缺失、检索证据不足和无依据回答问题，基于 nano-cc 进行轻量 Agent Harness 搭建和领域化改造，构建集 Query 改写、混合检索、证据反思、引用生成和会话记忆于一体的七阶段可追溯问答 Agent。

### 主要工作

1. 构建包含 N 篇垂直领域论文的本地语料库，采用段落与滑动窗口完成分块并保留论文、章节等元信息；基于 BGE-M3 与 BM25 实现稠密/稀疏双路召回，经 RRF 融合和 Cross-Encoder 重排序后封装为 `search_papers`、`retrieve_chunk` 等领域组件。
2. 复用 nano-cc 骨架，实现 `Guardrails → NLU → Retrieve → Rerank → Reflect → Generate → Memory` 七阶段编排。其中 NLU 通过结构化输出完成意图识别、指代消解与 Query 改写；Reflect 在证据不足时触发二次检索或主动拒答。
3. 扩展 `AgentState`，引入 Turn/Stage 两级 PipelineTrace，记录各阶段输入输出、工具调用、耗时及状态元数据；增加 `/trace`、`/corpus`、`/memory` 等 CLI 命令，并在原有上下文压缩机制上扩展会话记忆更新与按需压缩。
4. 构建 30 组四轮主对话（120 turns），并划分 100 条意图集、100 条检索集、55 条边界集及 70-turn 端到端集，覆盖指代改写、二次检索、越界拒答、证据不足和跨论文比较；实现 Intent Accuracy、Recall@5、拒答准确率、引用准确率、Pipeline Success Rate 及 Memory 一致性等组件级评测与消融实验。

### 项目成果（原作者数据）

- Intent 五分类准确率：89%。
- Query 改写准确率：82.6%。
- 混合检索 Recall@5：相比纯稠密提升 7.1 个百分点；加入重排序后再提升 3.2 个百分点。
- 边界 case 测试中拒答准确率：76.4%；Reflect 使证据不足子集的拒答准确率提升约 13 个百分点。
- Pipeline Success Rate：75.7%。
- 记忆压缩后对话一致性：80.3%。
- 平均 token 开销：降低 34%。

## 简历 05：乌影拍客——Hybrid RAG 乌类科普系统



### 项目简介

面向乌类科普多轮对话场景，基于 Node.js + Express 构建带混合检索与分层记忆的 LLM RAG 应用；通过异构文档解析、Dense/Sparse 双路召回、Cross-Encoder 精排与上下文扩展，为 GLM-5 提供高相关 Evidence 与用户记忆。

### 主要工作

1. **文档解析和嵌入**：使用 Docling 统一解析异构文档，标准化正文与元数据；采用固定长度分片并优先保持句子边界，使用 BGE-M3 生成 Chunk Embedding 写入 Milvus；通过 MySQL 管理文档、Chunk 正文及索引元数据。
2. **Hybrid Retrieval & Rerank**：使用 BM25 与语义检索，通过 RRF 融合两路 Top-N 排名进行检索，再通过 rerank 精细化重排并召回 Top-k。
3. **上下文扩展 & Memory**：对 Top-K 命中片段执行邻域扩展，并对连续区间合并去重，以缓解固定分片造成的语义割裂；维护最近对话窗口作为短期记忆，将用户稳定偏好与高重要度历史信息压缩为长期记忆并形成结构化记忆。
4. **查询重写 & RAG Generation**：结合短期对话将指代型输入重写为独立 Query 后执行检索；将 System Prompt、相关长期记忆、近期对话、扩展后的 Evidence Context 与当前问题分层组装后输入 GLM-5 生成回答，并通过 Node.js + Express + `async/await` 封装检索与对话 API。

### 技术栈

Node.js、Express、MySQL、BGE-M3、Milvus、BM25/RRF、GLM-5。
