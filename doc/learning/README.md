# ScholarRAG 学习文档

这套文档按“一个论文问答系统从 0 到 1 应如何构建”的依赖关系组织，而不是按当前目录从上到下解释。你可以把它当成一条重新实现 ScholarRAG 的路线：先搭出可访问的后端，再加入数据、检索和 Agent，最后接前端、Docker 与评测。

## 每章的学习方法

每章建议重复下面四步：

1. 先看“要解决的问题”，不要一开始就背类名。
2. 再看调用链，确认输入从哪里来、输出到哪里去。
3. 打开列出的源码入口，用搜索定位函数，不必一次读完整个大文件。
4. 完成章末练习，并记录一个能通过日志、测试或接口验证的结果。

## 重要说明

文档描述的是当前工作区代码，同时用更适合学习的顺序重新组织它。因此，学习顺序不等于仓库真实的 Git 提交顺序。

另外，本项目的 README、配置模板和源码并非每一处都完全同步。本文档以源码为准，并会标注能力的真实状态。例如 VLM 的配置与 `VisionService` 已存在，但应用启动阶段还没有把 VLM 实例传入 Agent 图，不能把它视为已在聊天主链路中启用的功能。

## 建议里程碑

```text
M0  能启动服务并访问 /api/health
M1  能创建会话并通过 /api/chat 返回一个最小答案
M2  能上传 PDF，并在 PostgreSQL 中看到文件元数据
M3  能把 PDF 解析成 PaperNode
M4  能把父子文档写入 Milvus
M5  能独立运行检索并看到来源页码
M6  能用单 Agent 根据检索结果回答问题
M7  能运行 LangGraph 多 Agent 主图
M8  能通过 SSE 在前端看到流式答案
M9  能用 Docker Compose 启动完整系统
M10 能用评测脚本衡量检索和生成质量
```
